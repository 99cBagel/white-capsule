# Findings — evaluation reports

Every evaluation of Snail32 lands here as a dated report, written by the
agent that ran it (playbook Step 8).

## Naming

`YYYY-MM-DD-evaluation.md` — one file per evaluation run.

## Report outline

1. Verdict (`recommend` / `conditional` / `not yet`) + one-line reason.
2. Comparison table (from `comparison.json`).
3. Commercial summary (prices dated).
4. Compliance gap + buyer obligations.
5. Risk register.
6. Unknowns list — everything the decision still depends on.

## Rule

A report is not done until it is saved here AND the working notes are
appended to `handbook.md` AND `state/` is updated. The next evaluation
starts from all three.

A report records product findings only — never who ran the evaluation,
what they asked, or when. Clean-book rule: if a line would record a
reader, leave it out.
